# Digest: Integration & feature coverage (round 1)

## Claims

- Pawnote is described by its own README as "A purrfect API wrapper for PRONOTE," an unofficial TypeScript wrapper around Index-Education's internal Pronote web API, explicitly "not affiliated with Index-Education or PRONOTE in any way." — Source: Pawnote (LiterateInk/Vexcited), README via unpkg mirror (https://unpkg.com/pawnote/README.md), npm page https://www.npmjs.com/package/pawnote, accessed 2026-09-09, confidence: high, class: landscape

- Pawnote exposes typed access to: homework/assignments (including marking a homework done/not done), grades/averages/evaluation periods, timetable (retrievable per week or via from/to date ranges), attendance (absences, punishments, and delays), discussions (listing available discussion categories/threads, messages, and recipients), and personal/school (établissement) information. — Source: Pawnote TypeDoc API reference (https://gabriel29.alwaysdata.net/), cross-checked against feature summaries surfaced via web search of pawnote.js.org and npm listing, accessed 2026-09-09, confidence: medium (derived from an AI-summarized fetch of the TypeDoc site rather than a direct quote-for-quote read of source code; not independently re-verified against raw HTML), class: version/compat

- Pronotepy (Python, bain3/pronotepy on GitHub) exposes grades (with score/out-of-max and iteration over all grades), periods (trimesters/semesters), homework (shown in its example.py), timetable/lessons ("getting all lessons in a given timespan"), absences (including a teacher-absences data class), discussions, and user/school info (e.g. `client.info.name`). It explicitly does not use the official "HYPERPLANNING" API (which Pronote does not expose to students) — it works against the same student/parent-facing web endpoints pawnote targets. — Source: bain3/pronotepy README (https://github.com/bain3/pronotepy/blob/master/README.md) and readthedocs (https://pronotepy.readthedocs.io/), accessed 2026-09-09, confidence: medium (fetched via AI summarization tool rather than raw text diff, but consistent across two independent fetches), class: version/compat

- Pronotepy supports session persistence via `client.export_credentials()` / token reload (`python3 -m pronotepy.create_login`), and its README references ENT (Espace Numérique de Travail) authentication as a supported-but-community-maintained path, directing ENT-specific questions to a named contributor ("Bapt5") — implying ENT support in pronotepy is real but per-ENT and maintained ad hoc rather than centrally guaranteed. — Source: bain3/pronotepy README, accessed 2026-09-09, confidence: medium, class: pattern

- Pawnote's authentication surface (as summarized from its npm README/docs pointers) includes: basic username+password+Pronote-instance-URL login, username+"next time token" login (token-based session resume), and QR-code-based login. Token-based (next-time-token) login is documented to fail against Pronote demo servers, detectable via an `isDemo` property on the returned Pronote instance. — Source: Pawnote docs summary surfaced via web search (pawnote.js.org / npm v0.20.x README snapshot), accessed 2026-09-09, confidence: medium, class: version/compat

- There is a direct contradiction in pawnote's own documentation history on ENT support that could not be fully resolved in round 1: one cached doc snippet states "ENT native support is not and will never be supported by Pawnote... implementing each of them with every specificities requires a lot of time and effort," while another (from a more recent npm version's docs, v0.20.x era) states pawnote "supports basic (username/password/url) authentication, CAS/ENT authentication, Toutatice (via Educonnect), and generic ENTs (enabled for most ENT, still testing)." An older npm README snapshot (v0.7.0) shows an `authenticateFromENTCookies` function marked "not done yet" at that time. — Source: mixed web-search-surfaced snippets of pawnote.js.org / npm README versions 0.7.0 and ~0.20.x, accessed 2026-09-09, confidence: low (conflicting, unresolved — see below), class: version/compat

- Real-world confirmation that pawnote-based ENT login does work in production: the "konnectors/pronote" project (a Cozy personal-data connector) states it "retrieves your student data and files from Pronote using the Pawnote open-source library" and explicitly supports "Standard username/password authentication with a Pronote URL," "CAS/ENT authentication, including Toutatice (via Educonnect) and generic ENT systems." It fetches student data, timetable, homework, grades, attendance, and reports, and runs as a Node.js-based Cozy konnector (i.e., pawnote is consumed from a Node.js backend in production, not from a browser). — Source: github.com/konnectors/pronote (fetched via WebFetch AI-summary), accessed 2026-09-09, confidence: medium, class: pattern

- Reconciling the above: pawnote's core library appears to deliberately avoid re-implementing every French ENT's specific login UI/flow itself (hence "ENT native support is not... supported by Pawnote" as a core-library design stance), but it exposes a lower-level primitive — an "authenticateFromENTCookies"-style function — that accepts cookies obtained by *some other* ENT-login mechanism and completes the Pronote-side handshake, returning a reusable token. Downstream consumers (like the Cozy konnector) implement the ENT-specific scraping/login themselves and hand pawnote the resulting cookies. This is inferred/reconciled by this researcher from the conflicting snippets above and is NOT a claim taken verbatim from one source — flagged for follow-up verification against the actual pawnote source/API reference rather than search-engine summaries. — class: pattern, confidence: low (reconciliation, not a direct source claim)

- Pawnote's official documentation domain (docs.literate.ink and its subdomains pawnote.docs.literate.ink / js.pawnote.docs.literate.ink) is currently unreachable: a direct fetch of https://docs.literate.ink/pawnote returns a Porkbun "domain for sale" parked page, and DNS resolution fails for the subdomains, indicating the literate.ink domain has lapsed/expired as of the research date. This materially degrades pawnote's current documentation availability. — Source: direct WebFetch of https://docs.literate.ink/pawnote (returned Porkbun parking page) and DNS failures (ENOTFOUND) on pawnote.docs.literate.ink and js.pawnote.docs.literate.ink, accessed 2026-09-09, confidence: high, class: landscape

- No evidence was found that pawnote requires a browser/headless-browser runtime (Puppeteer/Playwright) for its core, non-ENT authentication and data-fetching flows; it is distributed as a plain npm package (`npm add pawnote`, also pnpm/yarn/bun) and is consumed directly from a Node.js backend in the konnectors/pronote project (a server-side/Node.js data connector, not a browser extension). This is consistent with it being a from-scratch HTTP+crypto reimplementation of Pronote's protocol rather than a browser-automation wrapper. However, this was not confirmed against pawnote's own architecture docs (those pages are down — see above) or its source code directly; it is inferred from install instructions + one real-world consumer's runtime. — Source: unpkg README mirror (installation section) + github.com/konnectors/pronote runtime description, accessed 2026-09-09, confidence: medium, class: pattern

- Pronotepy is Python-only with no first-party Node.js bridge; its own README/docs point developers wanting a JS/TS solution toward "PRONOTE (ex. Pawnote) (JS/TS) or Blocksnote (JS/TS)" as alternatives, rather than offering a way to call pronotepy itself from Node. — Source: bain3/pronotepy README (fetched via WebFetch AI-summary), accessed 2026-09-09, confidence: medium, class: landscape

- A third-party project, "papillon-python" (Christian-Martins/papillon-python on GitHub), builds a REST API on top of pronotepy using the `hug` REST framework and lxml, and supports Docker deployment — i.e., pronotepy CAN be exposed to a Node.js/Next.js app over HTTP, but only by running it as a separate Python microservice/process; there is no in-process Node binding. — Source: web search result surfacing github.com/Christian-Martins/papillon-python, accessed 2026-09-09, confidence: low (title/description only, not fetched directly — no confirmation of maintenance status, last-updated date, or completeness of the REST surface), class: landscape
