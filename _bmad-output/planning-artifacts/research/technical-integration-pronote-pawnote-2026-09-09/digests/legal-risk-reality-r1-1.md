# Digest: Legal/ToS risk & implementation reality (round 1)

## Claims

- On April 30, 2021, the open-source library "pronote-api" (Litarvan/pronote-api, a widely-used JS/TS reverse-engineered Pronote client) was shut down at the direct request of Index Education, the maintainer wiped the Git history and deleted the npm package. The maintainer's own notice, quoted from the repo, stated: "A compter du 30 Avril 2021, le projet 'pronote-api' est malheureusement arrêté à la demande d'Index Éducation," citing the legal risk that publishing such a client could constitute "la mise à disposition d'un programme informatique conçu pour permettre un accès frauduleux à un système de traitement automatisé de données (STAD)" (providing software enabling unauthorized/fraudulent access to an automated data-processing system, an offense under French law, i.e. the equivalent of unauthorized-access/CFAA-style statutes). — Source: repo maintainer notice, github.com/Litarvan/pronote-api, event dated 2021-04-30, accessed 2026-09-09, confidence: high, class: ecosystem-signal
  - Caveat: public forks/mirrors of the code continued to circulate after the takedown (per secondary summary), and other reverse-engineered libraries (pronotepy, pawnote) continued to be developed afterward, so the takedown did not end the ecosystem — it targeted one specific project.

- Index Education has published an official page addressing third-party apps (specifically naming the app "Papillon") stating: unofficial-app use is "not illegal in itself" ("Cette pratique n'est pas illégale en soi") because the user voluntarily supplies their own credentials and the app has no commercial purpose, but the company warns of (a) "automatic processing of school data for unapproved purposes" ("le traitement automatique de données scolaires pour d'autres finalités") such as bypassing school grade-display policies, and (b) data-protection risk that credentials/data could be "harvested or exploited by third parties without the user's knowledge" ("ses données soient récupérées ou utilisées à son insu par des tiers"). The page positions official PRONOTE as "the only school-life app qualified SecNumCloud SaaS" by the French state. — Source: Index Education, index-education.com/fr/article-1760-recommandations-relatives-a-l-application-papillon.php, accessed 2026-09-09, confidence: high, class: ecosystem-signal
  - Note: the fetch tool reported a footer date of "September 26, 2009" on this page, which is almost certainly a copyright/template year rather than the actual publication date of this Papillon-specific recommendation (Papillon as an app is recent) — treat the date as unverified/unreliable.

- Index Education's general corporate-site legal/CGU page contains a blanket prohibition on automated access to its sites, stating (French): "Utiliser des dispositifs, programmes ou autres méthodes pour accéder, acquérir ou surveiller tout ou partie de nos sites ou du contenu de ceux-ci" and "Utiliser tout dispositif manuel ou automatique permettant toute récupération de données sans notre autorisation expresse écrite" (no automated data retrieval without express written authorization). However, this specific page is the corporate website's legal notice, not a Pronote end-user (student/parent) product CGU — the fetch could not confirm this exact automated-access clause appears in the actual Pronote-product terms of use presented to students/parents at login, only that a separate "Conditions générales de vente et d'utilisation" document is referenced elsewhere. — Source: Index Education, index-education.com/fr/article-206-mentions-leacute-gales-et-condition-geacute-neacute-rales-d-utilisation.php, accessed 2026-09-09, confidence: medium, class: ecosystem-signal

- pronotepy (bain3/pronotepy, Python) is explicitly described by its own maintainers/docs as being "in maintenance mode": it will "continue to fix bugs and adapt to PRONOTE changes" but is not receiving new features; documentation/community sources point developers wanting active development toward newer libraries like Pawnote (JS/TS) or Blocksnote instead. — Source: pronotepy project (readthedocs/GitHub, via search-result summary), pronotepy.readthedocs.io, accessed 2026-09-09, confidence: medium, class: ecosystem-signal

- Recurring "cat and mouse" breakage pattern confirmed via pronotepy's own issue tracker: (1) Issue #334 (reported 2025-09-03, after upgrading to pronotepy 2.14.4) — the ac_orleans_tours ENT (a regional single-sign-on layer some schools use in front of Pronote) broke because the CAS login endpoint moved (ent.netocentre.fr → auth.recia.fr) and EduConnect started requiring an additional CSRF token pronotepy didn't send; the issue was closed as "not planned" with no visible maintainer fix. (2) A Home Assistant integration built on pronotepy (delphiki/hass-pronote, Issue #94) failed starting 2024-12-15 with an AES decryption/unpadding error during QR-code-token login ("Decryption failed while trying to un pad... probably bad decryption key/iv"), logged 14 times in under 10 minutes, with the issue left open and no maintainer response visible in the fetched content. — Source: github.com/bain3/pronotepy/issues/334 and github.com/delphiki/hass-pronote/issues/94, accessed 2026-09-09, confidence: high, class: pattern

- pronotepy's protocol internals are inherently fragile in a way independent of any single Index Education "attack" on the libraries: community-search summaries note "PRONOTE changes all of its object IDs every session," which breaks cached/stored object references (e.g. a `Lesson` object) between library versions/sessions — a structural reliability issue for any app that tries to persist Pronote data across sessions. — Source: search-engine synthesis of pronotepy community discussion/docs, accessed 2026-09-09, confidence: low (secondhand synthesis, not independently confirmed against a primary doc/issue in this round), class: pattern

- A downstream real-world consumer app built on top of these unofficial APIs, "yNotes" (EduWireApps/ynotes, open-source school-life app using both École Directe's and Pronote's unofficial APIs), is now archived/labeled "NOT MAINTAINED," with the stated reason being maintainer time rather than a specific legal action — illustrating that apps built on this ecosystem have a track record of going stale. — Source: github.com/EduWireApps/ynotes (via search summary), accessed 2026-09-09, confidence: medium, class: ecosystem-signal

- pawnote (LiterateInk/Pawnote, formerly Vexcited/Pawnote, TypeScript, the actively-maintained successor referenced in the brief) supports authentication "by username and password, or by username and token" per an npm registry summary — indicating some form of token-based re-authentication distinct from raw password each time exists, but this round could not retrieve pawnote's own README/docs directly (both github.com/Vexcited/Pawnote/blob/main/README.md and github.com/LiterateInk/Pawnote.js returned HTTP 404, npmjs.com/package/pawnote returned HTTP 403, and js.pawnote.docs.literate.ink failed DNS resolution) to confirm exact mechanics, whether this token avoids storing the raw password long-term, or any encryption-at-rest guidance. — Source: npm registry search-result summary (page not independently fetched), npmjs.com/package/pawnote, accessed 2026-09-09, confidence: low, class: ecosystem-signal

- pawnote's own documentation states ENT (regional SSO layers like EduConnect/AC-Orleans-Tours) native support "is not and will never be supported by Pawnote, as implementing each of them requires a lot of time and effort" — meaning any school that fronts Pronote with an ENT login is explicitly out of scope for this library, a direct reliability/coverage gap for real deployments. — Source: pawnote GitHub/npm README (via search-result summary), accessed 2026-09-09, confidence: medium, class: ecosystem-signal
