Résumé exécutif

Aucune des deux librairies "actives" candidates n'est dans l'état où le brief d'origine les avait laissées. pawnote (TypeScript, la piste privilégiée du brief) n'a publié aucune version npm depuis 11,5 mois high ; son auteur a quitté GitHub pour un hébergement auto-géré, et le projet qui en reprend le nom est désormais écrit en Rust, sans successeur TS maintenu identifié disputed. pronotepy (Python) est réellement vivant (dernier commit il y a 6 jours high) mais volontairement en "mode maintenance" et sans pont natif vers Node.js.

Le risque légal n'est pas théorique : un précédent confirmé (fermeture de "pronote-api" en 2021, motif pénal français) high existe ; Index Éducation a depuis assoupli son discours public ("pas illégal en soi" sous conditions) mais reste dissuasif.

Recommandation : pronotepy via un micro-service Python léger, plutôt que pawnote figée — seule pronotepy reçoit encore des correctifs quand Pronote change quelque chose. confiance moyenne

Plus grosse réserve : support ENT réel de pawnote non résolu disputed, et nature exacte du projet Rust index-education/pronote non confirmée low.

1. Santé de l'écosystème & paysage des candidats

Motif récurrent : chaque génération de librairie finit par recommander la suivante plutôt que de continuer à évoluer.

  • pronotepy (Python) — dernier commit 2026-09-03, v2.15.7 le même jour, 235★, 30 contributeurs high — mais "mode maintenance" revendiqué : "We will continue to fix bugs and adapt to PRONOTE changes, but will not be adding new features." [3]
  • pawnote (TypeScript) — deux dépôts GitHub (Vexcited/Pawnote, LiterateInk/Pawnote.js) en 404 ; npm gelé depuis 2025-09-21 (v1.6.2) high [2]. Cause : l'auteur a migré vers un hébergement auto-géré ("GitHub is not a safe place anymore") [5], pas un abandon pur.
  • Le projet reprenant le nom sur l'instance de l'auteur (index-education/pronote) est listé comme Rust, mis à jour 2026-06-21, sans successeur TypeScript maintenu identifié medium [6] — identité exacte avec l'ancien Pawnote non confirmée.
  • Blocksnote (TS, MIT) — alternative indépendante confirmée, mais petite (13★) medium [7].
  • pronote-mcp (candidat signalé par l'utilisateur) — écarté : serveur MCP pour Claude Desktop, pas une librairie backend ; verrouillé sur l'ENT "Monlycée" (lycées d'Île-de-France uniquement) ; 1 release depuis avril 2026 ; identifiants en clair high [21].
  • Précédent historique : pronote-api (Litarvan), l'ancêtre commun, arrêté le 2021-04-30 à la demande d'Index Éducation high [8].

2. Fonctionnalités exposées & réalité d'intégration

Même périmètre de données pour les deux librairies actives : devoirs, notes/moyennes, EDT, absences, discussions, infos établissement [10].

  • pawnote — paquet npm pur, consommé directement depuis Node.js en production (connecteur Cozy) medium [11]. Aucune preuve qu'il nécessite Puppeteer/Playwright [9].
  • pronotepy — Python pur, sans pont Node natif ; son propre README renvoie vers pawnote/Blocksnote pour du JS/TS medium [12]. Un wrapper REST tiers existe, maintenance non vérifiée low [13].
  • Support ENT (Toutatice, Éduconnect, CAS) — sources contradictoires sur pawnote (une doc dit "jamais supporté", une autre dit "supporté") disputed [14]. Preuve empirique en faveur du support réel : le connecteur Cozy l'implémente en production [11].
  • Documentation officielle de pawnote (docs.literate.ink) expirée, page de revente de domaine high [16].

3. Risque légal/CGU & réalité d'implémentation

Précédent confirmé (2021) : "la mise à disposition d'un programme informatique conçu pour permettre un accès frauduleux à un système de traitement automatisé de données (STAD)" high [8]. Position actuelle plus nuancée d'Index Éducation : "Cette pratique n'est pas illégale en soi" si identifiants fournis volontairement et sans usage commercial high [17] — mais met en garde contre la récupération de données par des tiers.

Casse périodique documentée, pas hypothétique : issue pronotepy #334 (ENT ac_orleans_tours cassé, fermée "not planned") et hass-pronote #94 (erreur de déchiffrement AES depuis déc. 2024, sans réponse) high [19]. Une app aval ("yNotes") est désormais archivée "NOT MAINTAINED" medium [20].

Insights croisés

  • La librairie la mieux intégrée au stack (pawnote) est la moins vivante ; la plus vivante (pronotepy) est la moins bien intégrée — aucun candidat ne gagne sur les deux axes.
  • Le risque légal ne différencie pas les candidats entre eux — il pèse également sur tous.
  • Motif "succession sans continuité" observé sur 3 générations de librairies — un remplacement futur est probable, pas exceptionnel.

Contre-arguments

Pas de passe red-team exécutée (désactivée par défaut). Points trouvés en cours de route qui jouent contre la recommandation :

  • Contre pronotepy : second runtime Python dans un projet 100% Next.js/Node — coût réel, même si Vercel propose des fonctions serverless Python (non vérifié cette session).
  • Contre "pawnote abandonné" : l'auteur est actif ailleurs (Rust, mis à jour en juin 2026) — migrer d'écosystème n'est pas disparaître. La version npm 1.6.2 peut rester utilisable longtemps.
  • Contre le risque légal comme facteur bloquant : aucune action spécifique contre pronotepy/pawnote trouvée — les deux sont distribués publiquement 4+ ans après le précédent de 2021.

Recommandations

  1. Ne pas implémenter Pronote maintenant sur la base du choix pawnote du brief d'origine — il est obsolète. confiance haute
  2. Retenir pronotepy comme candidat principal, exposé via une fonction serverless Python légère (faisabilité Vercel/palier gratuit à confirmer séparément). confiance moyenne
  3. Isoler l'intégration derrière une interface interne stable — remplacement futur probable vu l'historique de succession. confiance haute
  4. Traiter le risque légal comme principe de conception : identifiants saisis par l'utilisateur final, chiffrement au repos, pas de republication, pas d'usage commercial. confiance moyenne
  5. Revérifier ce choix juste avant l'implémentation réelle, pas seulement avant la planification. confiance haute

Questions ouvertes

  • Le dépôt Rust index-education/pronote est-il la continuation directe de Pawnote, ou un projet distinct réutilisant le même slogan ?
  • pawnote supporte-t-il réellement l'authentification ENT nativement, ou seulement via une primitive bas niveau ?
  • Vercel supporte-t-il des fonctions serverless Python dans le palier gratuit avec un cold-start acceptable ?
  • Quel ENT (s'il y en a un) utilise l'établissement réel visé par CartableFlow ? — posé à l'utilisateur, réponse en attente.
  • La clause CGU corporate d'Index Éducation figure-t-elle réellement dans les CGU produit Pronote présentées à l'élève/parent ?
